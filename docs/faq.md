# 常见问题

## 为什么不用现成的"一键脚本"？

一键脚本假设机器是长期的、IP 是固定的。**抢占式实例两条都不满足**：
机器随时被回收、IP 每次都变、密钥也会变。这个项目的绝大部分代码在处理这件事。

## 为什么是抢占式实例？

便宜。实测香港 2C2G 的竞价市场价约 **0.02 元/小时**，比按量付费低一个量级。
代价是随时可能被回收，所以配了保护期 + 自动重建 + 凭据持久化。

## 一年大概花多少钱？

实例费按 0.02–0.05 元/小时算，流量约 0.5–0.8 元/GB。
个人用法（每天几小时 + 几十 GB）大约**每月 ¥20–50**。
真正的变量是流量，所以有 `budget.max_gb` 闸门。

## 为什么需要域名吗？

**不需要。** REALITY 不需要域名和证书，直接用 IP 就行。

"换 IP 后客户端不用重配"这件事，我们是用**凭据持久化 + 手机订阅端点**解决的：
机器重建后凭据不变，订阅内容自动更新——不用买域名、不用对象存储。

## 会不会被墙？

REALITY 的伪装质量取决于你选的**伪装目标**（dest）：要求从香港可达、支持 TLS1.3、
**证书链不能太长**——最后这条是硬约束，`www.microsoft.com` 实测必挂。
工具会按候选列表逐个实测，用第一个真正通的。

IP 层面的封锁无法完全避免。路线图里有"抗墙自动处置"（换端口 / 换 dest / 换 IP）。

## 能用 Clash / sing-box / Shadowrocket 吗？

能。`~/.config/yi/profiles/` 里同时生成 mihomo（Clash 系）与 sing-box 配置，
以及通用的 `vless://` 链接。协议是标准的 VLESS + Vision + REALITY，
任何支持 Xray 内核的客户端都能用。

## 为什么不自己写协议？

代理协议是安全敏感的东西，成熟内核（Xray / mihomo）经过大量实战检验。
我们只做编排：买机器、装服务端、管状态、把界面做清楚。

## 我的密钥安全吗？

三种密钥分开看：

| 密钥 | 在哪 | 说明 |
| --- | --- | --- |
| 阿里云 AccessKey | 本机 `~/.aliyun/config.json`（600） | 建议用 RAM 子账号最小权限 |
| SSH 私钥 | 本机 `~/.config/yi/id_ed25519`（600） | 从不离开本机 |
| REALITY 私钥 | 本机 `~/.config/yi/identity.json`（600） | **这是"重建后客户端不用重配"的代价** |

服务端上**没有** AccessKey；本机上也**没有**服务端私钥以外的敏感物。
详见 [SECURITY.md](../SECURITY.md)。

## 支持 Linux / Windows 吗？

命令行部分（Python + 标准库）理论上跨平台，但系统代理与打包目前只做了 macOS。
欢迎 PR。

## 会不会自动扣很多钱？

不会。创建的所有资源都带 `ttl` 标签；`yi status` 显示已运行时长与流量；
创建失败会自动回滚，不留孤儿资源；`down --orphans` 能按名字前缀清理残留。
唯一的风险是你忘了 `down`——记得用 `yi watch` + `budget` 上限兜着。
