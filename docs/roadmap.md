## 下一步

### 抗墙自动处置

三种封法分开对付：

| 封法 | 现象 | 处置 |
| --- | --- | --- |
| IP 被封 | TCP 完全不通 | 换 IP（重建实例） |
| 端口被封 | 换端口能连 | 服务端同时监听备用端口 |
| SNI 被封 | TCP 通但 TLS 被 RST | 换伪装目标 |

检测在**本地**做（因为是本地这条路被墙），且判定要连续多次才动手。

### 手机订阅的异地稳定入口

现在依赖"手机和电脑在同一 Wi-Fi"。要在蜂窝网下也自动更新，
需要把订阅放到一个固定 URL（对象存储），保持零域名依赖。

## 明确不做

- 不做多用户计费、不做对外售卖、不做面板式规则编辑器
- 不自己写代理协议——成熟内核已经很好，重复造不如把编排做可靠
- 不自研 Android 客户端——`VpnService` + 内核集成 + 证书管理是一整套工程，
  重写只会比 v2rayNG 更差。我们负责把客户端交到你手上（`yi android`），
  以及生成能被它直接导入的订阅
