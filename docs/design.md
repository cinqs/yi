# 界面设计系统

> "好看"不是审美问题，是**信息层级**问题。emoji 当图标、所有卡片同权重、
> 没有字阶——这三样凑齐，无论用什么配色都会像作业。

## 设计令牌

颜色只在一层定义，组件里不出现裸色值：

```
背景     --bg #0B0E14      表面 --surface / --surface-2 / --surface-3
文字     --text #E9EDF6    --text-dim / --text-faint
品牌     --brand #6B8AFD   （与 App 图标同色）
语义     --info #6B8AFD    --warn #E4B363    --danger #E8756F
```

**为什么是这一套**：底色是**冷灰蓝**（近黑带一点蓝），品牌色是**雾蓝紫**。
换成这一版的理由是旧版的祖母绿饱和度太高、辉光又重，整体偏"电竞外设"；
新配色把饱和度压下来、辉光收敛到只在"已连接"时出现，层次交给表面明度和
发丝线去做。同一套色值贯穿 App / 落地页 / 图标 / 社交预览图 —— 任何一处
单独改都会立刻显得不搭。

**分层靠"表面明度"而不是描边**：`surface → surface-2 → surface-3` 递进，
再加 1px 发丝线、极淡的顶部内高光、分层阴影。

## 字阶

| 角色 | 规格 |
| --- | --- |
| 小标签 | 11px / 字距 .09em / 大写 / 低对比 |
| 正文 | 13–14px |
| 数值 | 等宽 + 右对齐（`tabular-nums`），扫读时对齐 |
| 主角 | 27px / 680 字重 / 负字距 |

## 图标

**全部自绘 SVG**（15 个，24×24 网格、1.7 线宽、`<symbol>` + `<use>`）。
用 emoji 是"作业感"的头号来源——它的基线、粗细、色彩都不可控。

## 状态光环

界面的视觉主角是一个 SVG 圆环 + 品牌色图形：

- **进度环**：安装时按真实阶段推进，连接时闭合
- **图形**：地球（空闲）/ 盾牌（已连接）/ 服务器（机器页）/ 警示（异常）
- **动效**：连接时外圈呼吸光晕，忙碌时进度弧扫光

## 动效原则

- 状态切换用 `transition`（颜色 .25–.35s、位移 .22s）
- 进度条用 `cubic-bezier(.22,1,.36,1)`，有"到位"的手感
- 提示（toast）从底部滑入，4 秒后淡出；**不打断操作**
- 破坏性操作（销毁机器）才弹模态确认，且是**页面内**对话框，
  不依赖宿主是否支持 `window.confirm`

## 交互原则

- **每一处可点的东西都要有反馈**：hover / active / disabled 三态齐全
- **按钮忙碌时禁用并转圈**，不要让它看起来还能点
- **首屏直接给真实数据**（后端把状态内联进 HTML），不要先画骨架屏再跳一下
- 骨架屏只在真的拿不到数据时用

## 已知的 CSS 陷阱

通用态里只要带 `:hover` 或 `:not()`，**选择器权重就会反超**只有一个修饰类的变体规则。
所以变体必须把自己的所有状态补全——否则会出现"悬停后主按钮变灰、底部还留着绿光"
这种怪样子（真被用户抓到过，见 [lessons.md](lessons.md)）。
