## 下一步

### 抗墙自动处置

现在的自愈覆盖"机器没了"，还不覆盖"机器在但被封了"。

计划：检测端口封锁 → 自动换端口；检测 SNI 封锁 → 自动换伪装目标；
检测 IP 封锁 → 自动换 IP。

**难点不是检测，是"换"的动作要快且不能让用户断网**，所以会走调和循环那套，
而不是单独写一条应急路径。

### 手机订阅的异地稳定入口

现在的手机订阅只在**同一个 Wi-Fi 内**可用（因为地址是本机局域网 IP）。
要在蜂窝网下也能自动更新，需要一个稳定入口——
最便宜的做法是对象存储放一份订阅文件（**不需要域名**）。

## 明确不做

写下来是为了以后不被反复问，也是为了让 PR 有依据：

| 不做 | 原因 |
|---|---|
| **自己实现代理协议** | 细节多到能吃掉整个项目，而且写错了是静默的 |
| **多用户 / 商业化** | 会引入计费、限额、审计一大堆东西，和"个人自用"的定位冲突 |
| **域名 + 证书 + CDN 方案** | 必须有域名，违反"极便宜"的初衷。REALITY 天生不需要 |
| **Windows / Linux 客户端** | 服务端跨平台；客户端目前只投 macOS。生成的 mihomo / sing-box 配置可直接在别处用 |
| **内置机场订阅、节点分享** | 这不是那类工具 |
| **遥测 / 崩溃上报** | 用隐私换开发便利，这笔账在代理工具上不划算 |
