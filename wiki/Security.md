# 安全与隐私

## 威胁模型

理解它才能判断什么算漏洞：

| 资产 | 在哪 | 泄露的后果 |
|---|---|---|
| 阿里云 AccessKey | 你本机（`~/.aliyun/config.json` 或环境变量） | 别人能操作你的 ECS 资源 |
| SSH 私钥 | 你本机 `~/.config/yi/id_ed25519` | 别人能登录你的机器 |
| 代理凭据（UUID + REALITY 密钥对） | 你本机与客户端配置 | **别人能白嫖你的代理**（UUID 即密码） |
| 服务端 REALITY 私钥 | 只存在于服务器 | 别人能冒充你的服务器 |

## 默认做了什么

- RAM **子账号** + 最小权限；不用主账号 AccessKey
- SSH **仅密钥登录**，且安全组只放行**你当时的公网 IP**（`/32`）
- 本地敏感文件 `0600`、目录 `0700`
- agent **只监听 `127.0.0.1`**，不对外暴露
- 手机订阅端点带**随机 token**，且只读
- **不收集任何遥测**。除了阿里云 API，`yi` 只联系你自己的服务器
  （外加几个 IP 探测服务，用来知道自己的公网 IP）

## 已知的、可接受的取舍

这些**不算漏洞**，但你应该知道：

1. **REALITY 私钥会落在你本机**。这是"重建后客户端不用重配"的代价。
   不接受的话就删掉 `~/.config/yi/identity.json`——
   下次 `up` 会重新生成，客户端需要重新导入配置。
2. **手机订阅走明文 HTTP**（同一 Wi-Fi 内）。内容里含节点凭据，
   别在公共 Wi-Fi 上刷新。
3. **macOS App 未签名、未公证**，首次打开需要右键 → 打开。
   正式签名需要 Apple Developer 账号（$99/年），与"极便宜"的定位冲突。

## 如果你要对外分享服务器

不要。UUID 就是密码，**没有第二道门**。要多人用就每人一台，
或者换一套带多用户管理的方案（本项目刻意不做多用户）。
