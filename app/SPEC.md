# yi.app — macOS 一体化客户端 规格

状态：草案 v0.1 · 2026-09-20

## 1. 一句话

一个 macOS App：点一下就买好阿里云香港的机器、装好服务端、连上代理，全程看得见进度和状态。

## 2. 目标用户与场景

自己用代理的人（1 台机器 / 2–3 个设备）。痛点是**现在这条链路要敲 10 条命令、看懂 5 个日志**。
App 要把这些变成按钮和状态灯。

## 3. 范围

### 做
- 一键购买 + 安装（复用 `yi`，含竞价、保护期、dest 自动选择、回环自检）
- 机器状态面板：运行中/已停止/已被回收、IP、已运行时长、流量、花费估算
- 安装进度：把 cloud-init 的每一步实时显示出来（不是转圈）
- 连接开关 + 连接状态：当前节点、延迟、上下行速率、走了哪些规则
- **自动 IP 管理**：竞价被回收 → 自动重建 → 客户端无感（复用同一套凭据）
- **域名管理**：把域名 A 记录自动指向当前机器（阿里云云解析）
- **出口/线路管理**：多节点 + 自动选择 + 故障切换

### 不做（本版本）
- 多用户/多租户、对外售卖
- iOS / Windows / Android 端（下一步）
- 自建面板式的复杂规则编辑器

## 4. 架构

```
┌────────────────── yi.app (Electron 壳，最后一步) ──────────────────┐
│  UI (HTML/JS，无构建步骤)                                              │
│    ├── 首页：大按钮「启动代理」+ 状态灯 + 延迟/速率                     │
│    ├── 机器页：购买/销毁、状态、流量、花费、事件时间线                  │
│    ├── 连接页：节点列表、当前出口、延迟测试、规则命中                    │
│    └── 设置页：区域/规格/预算/域名/端口                                 │
└───────────────────────────┬───────────────────────────────────────────┘
                            │ HTTP + SSE (127.0.0.1:随机端口)
┌───────────────────────────▼───────────────────────────────────────────┐
│  agent（Python，复用 yi，零第三方依赖）                             │
│    ├── 生命周期：up / down / watch（竞价回收自愈）                       │
│    ├── 连接：mihomo 子进程 + 生成配置 + 系统代理开关（管理员授权）        │
│    ├── DNS：阿里云云解析 A 记录跟随当前 IP                              │
│    └── 事件：日志/进度统一成 SSE 推给 UI                                │
└───────────────────────────┬───────────────────────────────────────────┘
                            │
              ┌─────────────┴──────────────┐
              ▼                            ▼
        阿里云 ECS/云解析              mihomo 内核（代理）
```

**为什么 agent 和 UI 分开**：agent 可以直接被命令行、手机端、甚至别的 UI 复用；
UI 用什么技术都不影响后端。也方便**先在没有 Electron 的情况下测通全流程**。

## 5. 关键技术决策

| 决策 | 选择 | 理由 |
|---|---|---|
| UI 形态 | 先做本地 Web UI，最后套 Electron | 没有 Xcode/Rust 1.77，Electron 是唯一可行且成熟的壳；UI 先跑起来才不会被 100MB 安装包卡住 |
| 代理内核 | mihomo（Clash Meta） | 成熟、规则分流强、带 REST API 可查状态、支持 TUN；Clash Verge Rev 用的就是它 |
| 服务端协议 | VLESS + XTLS-Vision + REALITY | 已在 M1 验证；不需要域名和证书 |
| 后端语言 | Python（复用 `yi`） | 三个星期的调试成果都在里面（签名、容错、dest 选择、自检），重写是浪费 |
| 打包 | PyInstaller 把 agent 打成单文件，Electron 带它作为 sidecar | 用户不需要装 Python |
| 管理员权限 | 系统代理用 `networksetup`，通过 osascript 弹系统授权框 | 不需要常驻特权守护进程；TUN 模式再单独做 helper |

## 6. 与 `yi` 的关系

**agent 不重新实现任何东西**，它是 `yi` 的一层薄封装：
`src/yi/{aliyun,state,bootstrap,configgen,ssh}.py` 全部直接调用。
好处是 CLI 和 App 行为永远一致，修 bug 一处生效。

## 8. 里程碑

| 阶段 | 内容 | 验收 |
|---|---|---|
| A1 | agent：HTTP + SSE + `/state` + `/events` | 能启动、能读状态、日志能实时推给 UI |
| A2 | agent：`/provision` `/destroy` 接 `yi up/down` | 点一下能真的买到机器，进度条按阶段推进 |
| A3 | Web UI：三屏能跑通（购买→进度→连接） | 浏览器里完成全流程 |
| A4 | agent：`/connect` `/disconnect` 控 mihomo + 系统代理 | 点一下开关，浏览器出口变化 |
| A5 | 自动 IP 管理：后台 watch + 凭据复用（重建后客户端无感） | 杀掉实例，2 分钟后自动恢复且**无需重新导入** |
| A6 | 域名管理：A 记录跟随当前 IP | 域名始终指向活着的机器 |
| A7 | Electron 壳 + PyInstaller 打包成 `.app` | 双击打开，不是浏览器 |

## 9. 抗墙（GW / GFW）管理 —— 用户明确要的功能

用户口中的「gw 管理」= **大陆防火墙的对抗**：被墙了要能发现、能自己换。

### 9.1 三种封法，要分开对待

| 封法 | 现象 | 处置 |
|---|---|---|
| **IP 被封** | TCP 完全连不上，或只有大陆方向不通 | 换 IP（销毁重建 / 换 EIP）；必须有稳定入口让客户端无感 |
| **端口被封** | 换端口能连，原端口不通（443 常被盯上） | 切备用端口（8443/2053/2087…），服务端要同时监听 |
| **SNI / 指纹被封** | TCP 能连但 TLS 握手被 RST（`unexpected eof`/`connection reset`） | 换伪装目标 dest（我们有候选列表 + 自检），必要时换协议 |

### 9.2 检测（在本地做，因为是本地这条路被墙）

- 每 N 分钟：TCP 握手 + **完整 TLS 握手**（不是只看端口通不通）
- 判定：TCP 成功但 TLS 被 RST → 高度怀疑 SNI/指纹被针对；TCP 就失败 → IP/端口被封
- 记录历史，UI 上画一条"线路健康度"时间线
- 判定要**连续多次**才动手（沿用今天学到的教训：单次 API/网络抖动不作为依据）

### 9.3 处置（按代价从小到大）

1. 换端口（秒级，服务端同时监听多个端口）
2. 换伪装目标 dest（分钟级，重建配置 + 自检）
3. 换 IP（几分钟，重建实例；靠凭据复用 + 稳定入口让客户端无感）

## 10. 已确认的决策（2026-09-20）

| 问题 | 结论 |
|---|---|
| Q1 gw 管理 | = 抗墙（检测 + 自动处置），见 §9 |
| Q2 域名 | **待定**：作用见下；可先用"固定 URL 订阅"替代 |
| Q3 机器数量 | **单台**，不做多节点负载 |
| Q4 凭据复用 | **做**。已实现：`src/yi/identity.py`（UUID + REALITY 密钥对持久化到 `~/.config/yi/identity.json`，0600，重建时注入新实例） |

### 关于域名（解释给用户）

客户端配置里现在写的是 **IP**。竞价实例一被回收重建，IP 必变。所以：

- **只有凭据复用**：UUID/密钥不变了，但地址还是变 → 客户端仍要重新导入
- **凭据复用 + 域名**：配置里写 `hk.example.com`，A 记录自动跟随新 IP
  → 客户端**完全无感**（DNS 缓存过期即恢复）

替代方案（不用买域名）：把**订阅文件放在固定 URL**（如对象存储的静态文件），
客户端订阅一次，之后 IP 变化只改订阅内容，客户端自动拉新节点。
v2rayNG 和 mihomo 都原生支持订阅。
